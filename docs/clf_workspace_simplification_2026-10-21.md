# CLF 工作区优化（2026-10-21）

## 已完成

- 主流程为“选对象 → 描述规则 → 检查方案”。默认沿用当前项目；项目切换、路径和来源信息集中在折叠区域。
- 通过官方元数据模型一次读取紧凑的对象、CLF 和绑定目录，并沿用按源文件与桥接实现版本缓存的机制。无需逐个读取数千个 CLF 的引用来筛选。
- 规则按实际业务对象、维护入口及父类声明的绑定筛选，支持关键词、客户工作区筛选和每页二十条记录。相似名称不作为关联依据；动态调用不在已确认范围内。
- 常用模板包括必填、长度上限、数值范围、允许值、自定义规则。填写业务字段、时机、条件和提示后，一次提交到既有只读分析与官方预检流程。草稿按用户及对话保存在浏览器会话存储中。
- 规则详情优先展示名称、已有说明和已声明入口；“解释规则”“调整规则”“验证规则”集中提供。无可靠业务说明时明确标记需核对，不从技术名称编造规则含义。
- 方案优先展示业务要求、未决问题和修改前后的差异；完整操作参数、预演前后定义及来源均在技术详情中保留。
- 历史工具读取过程集中折叠，较长历史说明可展开查看。后续助手默认按“当前规则、本次调整、需要确认”简述，保留完整技术查询与原始回执。

- 选中规则后收起规则目录，直接呈现解释、调整和验证入口。页面资源会重新校验，避免浏览器沿用旧版本。

## 规则验证衔接

- 从规则进入测试页时携带对话、项目、规则名称及源哈希。源文件更新后阻止沿用过期链接，需显式刷新来源再核对。
- 默认复用与系统 WCF 地址匹配的已有业务连接和绑定客户端；账号密码不需要再次输入，也不从 SQL 或 Windows 共享凭据推定。
- 官方引用完整且其中的对象唯一对应真实 WCF 服务时，带入该服务。只有引用中的事件或方法能与该服务实际方法唯一匹配时才带入操作；其余情况显示“触发入口待确认”，不任意选择产品维护服务。
- 普通表单优先显示可用的名称、版本或容器名称等业务输入。连接、项目、客户端来源、JSON、返回字段和原始定义折叠显示，仍可展开使用。
- 默认结果仅显示当前规则与当前源版本的回执，其他记录保留在测试记录中。
- 本次写入开关、系统测试目标配置、来源校验、后台持久化、请求幂等性及真实 CLF 触发证据检查继续生效。

## 能力边界

本轮是操作流程与呈现优化，没有将 CLF 模式升级为文件保存、数据库发布或服务部署权限。模板是业务需求，不是已经验证的表达式；仍须读取实际函数、参数和绑定后预检。方案检查通过、文件保存、发布、业务验证分别记录。

复杂 CLF 的全部函数及原始表达式保留在技术详情中。摘要不替代完整语义，也不意味着任意业务服务都会触发当前规则。

## 验证

- 新增回归覆盖维护入口和父类关联、名称相似但无实际绑定、客户筛选、分页总数、对象标签搜索、继承环、源版本变化、会话归属、上下文保留以及默认连接保密。
- 全量测试：`python -m pytest tests -q`，**614 项通过、57 项按环境条件跳过**。
- 本机真实官方组件只读读取：4,289 个 CLF、3,341 个对象、5,792 个绑定；按 ShopFloor 及其父类筛选成功，工作 MDB 未修改。
- 浏览器使用隔离会话、隔离元数据与运行回执，结合真实生成客户端契约，验证对象选择、技术详情折叠、模板一次提交、方案差异、刷新后草稿与方案恢复、默认连接、入口匹配和测试回执。
- 本轮没有向实际业务环境提交测试写入，没有执行 Update Database。
