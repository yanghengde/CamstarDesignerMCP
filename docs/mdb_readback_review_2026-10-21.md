# 检查设计：读取 MDB 实际变更

第 6 步增加“读取 MDB 变更”，原手动按钮改为“人工审核确认”。读取结果不自动确认审核，也不执行 Compile、Update Database 或 WCF 生成。

## 数据来源与边界

- 使用 Camstar 官方 `CompareAndExport` 比较当前已保存的工作 MDB 与本轮最早基线；不把操作清单冒充实际读取结果。
- 比较在独立副本中执行，检查复制前后、返回前的工作文件和基线 SHA256，结束后清理读取副本。
- 展示字段、字段类型、存储列及其他定义的差异，并保留属性的旧值/新值、空值、嵌套引用。差异 XML 未提供旧值时，页面明确说明。
- 维护字段角色来自设计包记录的自动配套操作，不能根据对象名后缀推断。存储列另列，页面说明其不代表额外的业务字段。
- 已准备 Designer 文件时，首次读取前后、缓存命中时均检查已保存的交接文件。存在新修改时要求先保存、同步。不能读取 Designer 尚未保存的内存修改，也不推断 Designer 当前打开的文件。
- 缓存与 MDB、基线、SDK、桥接程序和读取实现的版本绑定。页面轮询只读取持久化回执，不重新启动 MDB 比较；展开的属性详情不被轮询关闭。

## 本机验证

当前 Spec 设计的只读实测：首次完整读取 **24.715 秒**，相同版本缓存读取 **1.472 秒**。这些时间包含文件校验及 Designer 已保存文件检查；不同文件大小和机器负载会影响耗时。

实际读到三项定义：

1. `Spec.ExSpecStatus`：新增业务字段。
2. `SpecChanges.ExSpecStatus`：自动配套维护字段。
3. `Spec.ExSpecStatus` 数据库存储列：同一业务字段的一列存储。

实测前后工作 MDB、Designer 交接 MDB 的 SHA256 相同；未更改当前流程确认状态。

回归覆盖实际差异与请求清单分离、版本缓存、连续设计基线、读取时文件变化、Designer 保存变化、属性前后值、持久化回执、人工确认保持独立及页面安全文本渲染。

后端修改需要服务重启后加载。本次没有重启正在运行的服务。
