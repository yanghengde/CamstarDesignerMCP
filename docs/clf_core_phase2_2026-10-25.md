# CLF 第二批实施：同页验证与工作 MDB 交付

> 后续声明参数表单和验收报告见 [第三批实施记录](clf_core_phase3_2026-10-25.md)。本文保留第二批交付时点的范围。

日期：2026-10-25。接续 [首批工作区](clf_core_implementation_2026-10-25.md)，按 [产品设计](clf_core_product_design.md) 与 [实施、验收合同](clf_core_delivery_and_acceptance.md) 推进。

本批交付覆盖同页输入/复现、真实回执查看，以及审核后的工作 MDB 保存、编译、快照恢复与项目发布检查。它是 G2 和 G4 的部分实现；不能登记为全部设计阶段已验收。

## 1. 操作方式

1. 在 `/clf` 进入工程排查，选择项目和规则，再进入“验证与排查”。输入、预期、用例、后台进度和结果在当前工作区完成。原 `/clf-test` 深链继续可用。
2. 从已有运行点击“复制为测试用例”。保持真实服务/方法、原输入、环境和源版本；清除写入授权，原回执不变。能无损表示的输入直接显示在表单；复杂或契约不匹配时展开 JSON 原文，不丢字段。
3. 修改规则时先准备方案，执行官方模型预检，核对原值/拟定值和完整回执。预检没有写入效果。
4. 在方案的“实施与交付回执”核对项目、差异和范围，再勾选审核项，明确点击“保存到工作 MDB”。仅保存当前项目工作文件，不自动复制到 Designer 服务器目录。
5. 保存成功必须包含官方保存后回读证据。随后可以编译已保存版本；发布检查在编译产物完整时开放，覆盖整个当前项目周期，包括其他已保存改动。检查不执行数据库发布。
6. 保存后可下载原快照、官方 XML 差异和清单。需要撤回本次工作文件保存时，可审核后“恢复本次保存前快照”；当前源必须仍等于该保存回执版本。有后续改动时拒绝覆盖。此恢复不是数据库或服务回滚。

## 2. 当前能力和限制

| 内容 | 本批实现 | 边界 |
|---|---|---|
| 同页验证 | 复用现有类型化编辑器和后台执行器，按项目/规则组织历史与用例 | 不新增第二条业务执行通道；服务器是否支持 Trace 仍取决于环境 |
| 输入恢复 | 当前标签会话保存有效输入、版本和用例来源；切换上下文先保存、再载入 | 不保存写入授权；含密码/令牌等敏感字段的草稿不持久化；未通过格式校验的半填输入仅保留在当前表单 |
| 上下文顺序 | 复现与上下文切换串行，防止晚返回的加载覆盖用户新选用例 | 模式和页签共用父工作区上下文；载入中表单不可提交 |
| 实际轨迹 | 以服务器原文的节点、属性、参数、耗时和层次展开，保留完整原文 | 显示上限 24 层、1000 节点；不从定义生成轨迹，不推断变量值，不强行关联函数行 |
| 官方保存 | 严格十类 CLF 操作、源版本校验、官方隔离副本、SaveAll、回读、差异和项目快照 | 声明参数完整生命周期仍未扩展；语义预期和真实业务验收独立 |
| 编译 | 原工作文件保持不变，记录编译输入和产物哈希 | 编译成功不代表数据库已发布、WCF 已生成或服务器来源一致 |
| 发布检查 | 复用项目周期发布规划，展示范围和阻止项 | 可读取既有目标元数据、生成本地规划；没有实际数据库发布按钮 |
| 恢复 | 验证快照和当前源后，采用保存前 MDB，保留原保存及编译回执 | 不覆盖后续版本；不自动恢复外部数据库或 WCF |

业务映射保存现在明确读取绑定身份，原普通助手的轻量 CLF 读取不变。CLF 对话仍为只读，新实施模块未注册为 MCP 写工具。现有本机用户归属机制继续使用，不能据此宣称企业多用户 RBAC 已完成。

## 3. 状态、幂等与失败处理

方案是不可变预检回执。实施请求明确指定 `plan_id`、`request_id`、动作、源 SHA-256 和审核状态；禁止未知字段和调用方注入新操作。

保存以用户 + 方案身份去重，不依赖浏览器按钮是否禁用。同一方案更换请求标识仍返回同一回执；同一身份搭配不同内容会拒绝。编译、发布检查和恢复也记录独立请求身份，重复请求不会重复执行。

| 动作 | 活跃状态 | 终态与含义 |
|---|---|---|
| 保存 | queued / saving | saved：已官方保存并回读；failed：未完成；needs_review：文件可能已变且完成证据不足 |
| 编译 | queued / compiling | completed：独立编译产物已生成，来源未变 |
| 发布检查 | queued / checking_publish | completed：本次检查结束，仍需查看 ready_for_publish 和 blockers |
| 恢复 | queued / restoring | completed：工作 MDB 恢复成功；原历史不改写 |
| 服务中断 | 任一活跃状态 | interrupted：需要核对已有文件和回执，不自动重放 |

执行前验证源版本，写入在项目锁内再次由既有管线校验。写入已发生但回读或回执不足时，不登记为成功，也不自动重试。恢复和下载都核验官方设计包完整性。服务正常关闭等待在途实施任务；非正常关闭的任务下次启动标为中断。

新增 `designer/clf_delivery.py`、`static/clf-testing-panel.html` 和 `tests/test_clf_delivery.py`。复用现有 SQLite 的 `clf_workspace_items`，新增 kind=delivery，不替换原测试历史或聊天表。新增接口：

- `GET /clf-testing-panel`：可信静态验证组件；前端按需加载原 `/testing.js`，不使用 iframe。
- `POST /api/clf/workspace/delivery`：接收明确动作，202 返回后台回执。
- `GET /api/clf/workspace/delivery?plan_id=...`、`GET .../delivery/{id}`：按归属读取阶段回执。
- `GET .../delivery/{id}/files/{baseline|changes|manifest}`：只下载已保存并通过完整性校验的官方设计包文件，不接收外部文件路径。

## 4. 验证证据

隔离验收项目使用用户工作 MDB 的副本和本机真实 Siemens SDK；业务传输替换为明确标记的隔离回执，没有连接真实业务环境。隔离产物、辅助脚本及浏览器证据位于 `tmp/clf-core-phase2`。

- 真实 SDK：复制 `ES_ValidateProduct` 为 `Ex_Core_Phase2_Acceptance`，执行官方保存、回读和差异导出；随后真实 MetadataCompile 成功，编译产物哈希匹配，工作源不变。
- 恢复演练：通过工作区恢复保存前快照，隔离源恢复为初始 SHA-256；原保存回执和编译记录仍可查看。
- 用户原工作 MDB 的初始 SHA-256 为 `7477440b95c05d9ca0d06d36e5c5f8853e92b287c65627844024e299518459df`。全过程只在副本写入，原文件校验保持一致。
- 浏览器同页验证：复制原运行保留 `ShopFloor / ES_ValidateProduct` 与真实契约字段 Comments，写入授权清零；通过既有后台执行器取得隔离成功回执，分层显示业务结果、断言、名称证据和待核对部署来源。
- 后端回归覆盖：归属、严格请求、审核、同方案去重、来源漂移、部分保存、恢复、重启不重放、编译来源、只检查不发布，以及下载完整性与归属。

正式测试目录回归命令 `python -m pytest tests -q`：657 项通过、57 项按环境条件跳过；Node 语法与差异空白检查通过。无目录限定的 pytest 还会收集忽略目录 `tmp/review_20261020` 中的历史审查脚本，其中有缺少专用 seed 配置及已修复问题导致的严格 XPASS；这些不是正式测试目录的回归失败，本批未修改该历史临时脚本。

浏览器验证有效输入刷新恢复、写入授权清零、项目/规则切换和复制时序；没有重复 DOM 身份或脚本错误。352 像素视口下可用宽度与文档 scrollWidth 均为 337。正式 8032 服务已重启并验证新组件、真实规则与默认环境加载，未提交真实业务交易。隔离结果截图为 `tmp/clf-core-phase2/single-page-result.jpg`。

隔离运行不是实际业务规则语义通过的证据，也不是对生产部署的验收。
