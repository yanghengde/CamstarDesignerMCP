# WCF 字段验收链路修复

## 本次故障

当前 Workflow 设计的 SDK 编译检查返回 `owner`、`name`、`present`，同时补充
`data_type`、`field_type`、`precision`、`scale`、`is_list`。服务入口仍只允许前三个键，
因此在真正开始生成前误拒绝合法结果。此前页面测试替换了整层生成函数，
原生生成测试又直接调用工作进程，两者都没有覆盖公共服务入口的衔接。

## 修复与相邻边界

- 在 `designer/wcf_contract.py` 统一字段结构、名称校验和生成结果验收。
  编译检查、MCP 工具 schema、服务入口、进度验收均使用该结构；保留旧的三字段格式。
- 未知属性、缺失属性、非布尔列表标志、非整数长度/精度、重复或冲突的规则，
  在远程任务开始前明确指出具体字段和属性。
- SDK 返回值不仅核对数量，也核对字段身份、存在性和完整类型信息。
- 现有厂商定义的验收仅检查名称语法；新建设计的保留字规则不用于拒绝已有字段。
- 公共生成入口与进度回读使用同一结果校验：来源未变化、计数有效、两端 DLL 齐全，
  并检查客户端/服务端字段存在性、类型和列表形态。冲突的同名契约不能被后一个结果覆盖。
- 部分服务生成保持部分标志，不能完成全量验收；界面移除过期的 20 个验收对象限制说明。
