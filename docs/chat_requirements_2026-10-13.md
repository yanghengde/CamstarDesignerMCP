# 运行中追加消息与修改需求

运行时保持输入框和发送按钮可用，停止按钮单独保留。用户可以在同一对话连续追加消息，原回答的连接与后台任务继续运行。页面显示补充内容及“已接收 / 正在纳入 / 已纳入处理”状态；“已纳入”只表示已进入本轮对话，不等同于设计保存或发布成功。

修改在完整工具操作之间应用。分析结束后、下一项工具开始前都会检查补充需求；正在保存的操作正常结束。明确修改会关闭尚未执行的旧调用，保留已执行回执，清除旧授权，并根据最新要求重新规划。新设计参数重新生成预览并等待确认。普通追问与表达偏好不会取消原批次；追问使用只读工具回答。运行中暂不替换 Excel 附件。

补充通过 `/chat/requirements` 提交，绑定用户、对话和本轮后台任务。客户端提交唯一消息标识，网络重试复用标识；同一标识不能改内容，已完成请求的确认也可重新读取。补充记录先保存再返回接收结果，页面离开或刷新后由历史接口恢复。任务恰好结束或进入确认时到达的已接收消息继续处理，已结束任务拒绝新消息并保留输入。

停止回答不会取消正在执行的保存。未处理的补充保留并标注需要重新发送；强制重启服务后同样保留，但不宣称任务仍在运行。正常服务关闭等待后台任务结束。

验证覆盖分析与保存期间修改、旧后续步骤不执行、新参数必须确认、普通追问只读、已确认 Excel 批次的部分执行状态、结束和暂停时的追加竞争、归属和过期任务检查、重试去重、停止和重启后的记录保留、输入框可用及切换对话时的界面隔离。使用隔离的模型、工具回执与会话目录，未调用厂商 SDK 或修改实际 MDB。
