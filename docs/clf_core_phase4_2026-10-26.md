# CLF 第四批：选择入口迁移并保留附着值

本批补齐声明参数副本方案中的事件入口迁移。参考本机 Siemens Designer 帮助 `06DesignCLFs/Adding_CLF_Parameters.htm`：已附着规则增加声明参数后，需要解除并重新附着。直接重新附着会读取库表达式，因此必须保护原入口的具体配置。

## 操作与范围

1. 在“工程排查 → 查看逻辑 → 声明与引用”准备声明参数变更，选择先复制客户规则。
2. 在同一弹窗查看真实入口及原表达式，明确选择需要迁移到副本的入口。默认均不选择；原规则和未选入口保持不变。
3. 原声明变更与入口迁移共同进入方案。差异表分别显示规则切换、入口身份及每项保留的表达式。
4. 官方内存预检通过后，仍需按原流程审核并保存工作 MDB。保存后重新加载，核对入口身份、目标、功能配置、参数身份、表达式和动态标记。
5. 沿用保存前快照恢复，不另建写入通道。预检和查看不保存工作 MDB，保存不代表数据库发布或业务验证。

本批支持当前客户工作区的对象/字段事件入口，目标为不同的独立客户 CLF。系统/非当前工作区入口和参数会显示原因，不能通过取消禁用或手工 JSON 绕过后台检查；本批不自动创建继承覆盖。直接规则调用者显示规则、调用 ID、顺序和工作区，仍指向原规则，需要后续单独迁移。

## 迁移合同

新增严格操作 `migrate_clf_binding`，包括 owner、field、event、binding_id、expected_clf、clf、expected_feature_id 和完整 expected_parameters。每个原参数保留真实 value_id、call_id、parameter_id、名称、表达式和动态标记。原值变化、遗漏、多报或重复身份均拒绝。

迁移前核对原规则与副本的全部调用顺序、官方函数身份、启用状态、参数身份及库表达式。重复函数按原调用身份和唯一顺序对应，不按函数名合并。调用结构或表达式调整请放到后续方案，不能与本批入口迁移混用。声明结构调整仍受现有引用检查约束，不自动改写表达式。

使用官方 `RemoveCLFFunParmAttachedToCLFFunction` / `CopyAllParametersFromCLF` 重新附着，再逐项恢复实际入口值。回读不一致视为未完整核验，由原保存管线处理，不能登记为成功。

## 后续范围

- 直接调用者及其所有入口的类型化参数迁移。
- 系统入口的显式客户覆盖和完整继承影响预览。
- 声明改名/删除的引用重写、动态引用识别及更多版本样本。
- 真实业务场景验证、部署来源与数据库/WCF 交付。

本批开发和验证不启动、停止或重启用户管理的 8032 服务。

## 验证记录

- 普通完整回归：`python -m pytest tests -q`，683 项通过、62 项按环境条件跳过。最后的前后端能力检测与接口变更另经相关回归，33 项通过、2 项跳过。
- 安装 SDK 专项：两项真实迁移测试通过。两个客户入口使用同一原规则，入口值为 `true`、库值为 `false`；只迁移其中一个入口。9 项附着值（含动态标记为 true 的参数）保存并回读一致，未选入口和原声明保持不变。
- 拒绝场景：参数清单缺项、原表达式变化、功能配置变化、迁移前调用结构变化、迁移后追加调用、非当前客户工作区入口。预检不会因此登记成功。
