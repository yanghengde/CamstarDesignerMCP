2026-10-14。重点防止创建失败、类型要求被忽略、同批部分成功和重复执行。继续使用现场 Designer 的 Camstar.Metadata 官方模型与隔离预检，不通过直接写数据库处理重名。

## 发现与处理

| 问题 | 优化后的行为 |
|---|---|
| 专用类型只按字段名生成，CreatedAtType 等容易跨对象冲突 | 自动类型名包含对象名、字段名和长度／Type 后缀；过长时保留前缀并添加稳定摘要，总长不超过 30；预览显示实际引用名称。已有定义仍由官方模型检查全局重名，不自动改名或复用 |
| field_type 与 data_type/precision/scale 同时填写时，后者被忽略 | 作为 expected_type 保留，使用实际 FieldDefinition 在创建字段或工作区覆盖前逐项比较；不符拒绝。max_length 与现有 field_type 同填继续明确拒绝，防止误认为会修改共享类型 |
| 重名只返回 Name already exists，难以判断是否可引用 | 字段类型冲突返回已有与请求的数据类型、精度、小数位和工作区；只比较已明确指定的形状，不以形状相同证明全部语义一致；提示核对后明确引用并移除新增操作 |
| 字段类型单独创建不进入聊天与执行入口的预检 | create_field_type 也在确认前及执行前通过只读预检 |
| create_table=true 缺少表描述，预检可过但 SaveAll 报零长度错误 | Python 参数校验和厂商桥均在创建前拒绝缺失／空白 table_description；文档示例补齐表描述 |
| 拼写错误和无效数值可能被忽略或被 .NET 转换 | 创建 CDO／字段类型／字段的未知键拒绝；专用字段字典未知键拒绝；布尔参数严格校验；同一对象字段大小写重名提前拒绝；精度和小数位须为非负整数，小数位不大于明确提供的精度；max_length 仅用于 String |
| 同批两个写调用修改同一 MDB，第二个仍带首次保存前哈希 | 确认前按真实工作 MDB 路径识别重复目标，包括种子／旧产物别名；要求合并到一次通用设计包，避免先保存第一批才发现第二批失效。不同 MDB 的独立写入保持允许 |
| 已完成操作返回空值时，重连可能再次执行 | 完成状态作为已执行依据，不依赖结果真假；持久化内部标量回执并支持恢复，旧版缺失输出也不会重做；内部输出脱敏并限制长度，不进入公开进度列表 |

定义名仍受 Designer 保留字、命名长度和官方工厂检查约束。对象类型、父对象、基础／继承字段、派生结构继续来自当前 MDB 与安装 SDK；不静默跳过冲突、覆盖已有字段或修改共享类型。
