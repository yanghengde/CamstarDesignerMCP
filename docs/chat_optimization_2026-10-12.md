# 聊天优化实施记录（2026-10-12）

本轮落实了[聊天审查](chat_optimization_review_2026-10-12.md)中的主要问题。完整会话、原始回执及审批门槛保留；没有执行用户工作 MDB 修改或数据库发布。

| 改动 | 实际行为 |
|---|---|
| 有界上下文 | 模型请求按完整工具消息组控制大小。大回执摘要标记为不完整，并带原始证据编号；历史文件和检查点不截断。当前完整需求超预算时提示拆分。 |
| 原始证据分页 | 新增只读 get_chat_evidence，限当前请求中的对话记录，可读取回执或附件消息原文。不接收任意文件路径，外部 MCP 调用无聊天上下文时拒绝读取。 |
| 当前任务记录 | 检查点保存目标、文字要求、拟定参数、附件证据和最新回执编号。明确的对象改名和建表要求在调用前检查；设计追问不改变原约束。旧检查点恢复时使用当前系统规则。 |
| 待确认追问 | 与原写入计划隔离的只读流程回答问题或查询定义。原预览及其参数指纹不变；追问记录持久保存并在确认/修改时正确拼接工具消息。 |
| 明确修改 | 改名、长度、工作区等修改作废原预览并重新规划。“新任务：……”重建任务需求并结束旧附件适用范围。 |
| 参数合同 | 通用工具 schema 要求 action 并列举有效动作。纯参数校验与函数签名核对发生在预览之前；CDO 操作构造由预览和执行共用。同类校验连续失败两次后停止。 |
| 回复偏好 | 明确的简短/详细、事实与下一步优先、减少道歉、避免重复选方案等偏好可保存。普通纠正仅作用当前会话，“以后/长期规则/记住”作用后续会话。只保存允许的表达选项，技术断言不自动成为长期事实。 |
| 失败重试 | 已失败的相同设计工具、参数和来源版本被阻止直接重试，需核验或改变有依据的输入。已有厂商流程继续处理来源变化、实际写入回读和失败副本证据。 |
| 确认证据 | 确认接收时间、预览 ID、调用参数指纹在恢复执行之前持久保存；确认预览显示时间。模型消息继续保持工具配对，不把其排列当作执行时间线。 |
| 并发保护 | 同一服务进程、同一会话同时发送消息时，后来的请求被提示等待，不覆盖正在处理的检查点。 |
| 回复规则 | 先说明本次结果、依据和下一步；复盘区分已证实原因与待核实事项，避免长篇自责和重复选方案。保存、发布、验收状态分别说明。 |

用案例的 90 条历史记录做只读测量：原 API 消息序列约 1,077,821 字符，压缩后的模型消息约 95,728 字符，减少约 91.1%。这是消息序列字符数，不是 token 数；不含工具 schema，也不表示首字耗时或准确率提高了相同百分比。

确定性验证覆盖大回执预算与原文回读、完整工具消息配对、超预算拒绝静默截断、待确认追问与反馈、只读查询隔离、SQLite 重启恢复、参数缺项、建表需求、重复失败阻止、偏好跨会话与重启、会话并发保护。

最终完整回归：263 项通过、8 项可选集成测试跳过；浏览器内联脚本语法检查通过。真实模型参数生成检查另行启用并通过。明确“其他不变”时会对照原方案字段属性，拒绝字段遗漏或变化，失败候选不能覆盖原对照方案。

新增可选真实模型检查：`CHAT_TEST_MODEL=1` 时运行 `tests/test_chat_model_integration.py`。使用当前配置模型生成隔离参数，不执行任何工具。改名样例已通过：对象与表名改为 AssetTrace_6382，OwnerEmail、String 长度 200、持久化和工作区 200 保留。该样例是有限的参数生成验证，不能视作全部自然语言场景或真实 MDB 建表流程均已验收。

表达偏好已有持久化入口；技术经验继续沿用现有经验候选审核。当前意图分类采用保守文本规则，未增加无界的自动自我训练；一般性技术反馈尚未全部结构化提取。自然语言事实核对主要通过证据上下文、流程门槛和回复规则加强，没有宣称所有句子都由独立核验器证实。同一会话的并发保护适用于单进程部署。

默认配置：CHAT_CONTEXT_CHARS=120000，CHAT_TOOL_CONTEXT_CHARS=6000。重启服务并刷新页面后生效。
