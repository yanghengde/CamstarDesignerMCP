# 对象创建预检与类别选择

2026-10-13，按对象创建 Review 落实优化。使用现场 Camstar.Metadata 10.6.0.0 的公开模型成员，不在 SQL 层修复字段重复，不重复执行 Update DB。

## 用户可见行为

- 提供命名主数据、版本化主数据、子实体／明细、业务服务、查询服务、历史记录六个分组。历史记录含 HistoryMainline 和 HistoryDetails 两个父对象。选择来自当前 MDB 中实际存在的父对象；明确指定 Product 等业务父对象时保留。
- 在待确认预览中显示类别、实际父对象、存储类别、全部基础字段及字段来源、系统用途、类型、长度／精度、持久化和列表属性。Product 的 160 个有效字段完整呈现，不能用前 100 个字段判断不存在。
- 显示厂商工厂预计生成的新表、Revision Base、Maintenance／Changes。是否生成由参数明确决定，便捷 CDO 工具支持这些选项，原默认值不变。
- 下拉改选父对象后生成修改要求草稿；发送后重做预检并生成新预览。当前方案保持原值，避免选择器显示与执行参数不一致。
- Name／name、继承字段、同批字段、生成结构重名均在保存前阻断。相同属性提示明确复用，不会静默跳过；不同属性提示改名或走允许的客户覆盖操作。不同对象可以有同名业务字段。

现场厂商 GetUniqueCDOName 会在 Maintenance 名称冲突时自动追加 `_1` 等后缀。预检检查工厂实际产生的对象／表名称，识别已有名称与数字后缀，报告现有名称和自动生成名称并阻断；不按猜测的 Maint／Base／Changes 模板自行生成派生结构。此后缀行为属于已测试安装版本，升级时需重跑边界验收。

类别未确定时由助手查询真实选项并让用户明确；无需每次重复选择已确定的父对象。用途掩码目录有多个产品内部组合，不直接作为用户类别菜单，也不由模型猜组合位。

## API 与保护

新增 `inspect_designer_creation_plan(mdb_file, expected_sha256, operations, workspace)`；operations=[] 只查询常用类别。返回 ready、conflicts、objects、categories、complete、来源与组件哈希；每个基础字段列表包含 total_fields 和完整性标记。

预检复制来源 MDB，在隔离图上按完整操作顺序使用 CreateNewCDO 等既有官方 API，直接读取 AllFields 和 FieldDefinition。预检不调用 SaveAll／导出／编译，不提交工作 MDB。前后核对来源、副本、SDK 和桥接哈希；副本立即释放。缓存绑定这些来源与完整请求；字段数不一致拒绝使用。

聊天策略节点在确认前预检，厂商设计执行入口在保存前再次检查。预览身份包含完整预检结果；用户确认后恢复工作流重新预检，来源、SDK 或规则变化使旧预览失效，需要核对新预览。参数改动仍使用既有作废与重规划流程。

通用 patch 禁止对象用途、父对象和存储类别属性及 ID。父对象变更使用 change_parent 的用途一致与继承关系检查；存储类别使用 change_storage_category。现有继承客户覆盖和字段类型变更 API 保持受控操作，不把冲突自动转换成覆盖。

本次 UI 预览截图使用真实 SDK 的只读结果及本地隔离响应，未创建截图示例中的业务对象。当前运行中的 Python 服务没有自动重载，重新启动工作台服务后新工具及聊天策略生效；静态页面刷新读取新版本。

## 验收

单元回归覆盖参数合同、缓存失效、来源／副本／组件漂移、截断拒绝、保存前阻断、预览身份、聊天重名拦截及 SDK 变化后的旧确认失效。

安装 SDK 验收在当前工作 MDB 的临时副本上进行，检查 Name／name、Description 长度差异、完整 160 字段、同批大小写重名、不同对象同名、Maintenance 和表名称冲突、实际生成结构、只读属性。测试结束确认原 MDB 与临时来源副本 SHA256 不变。

界面实际检查：完整列表 160 行；Product 改选 NamedDataObject 后输入框生成重新预检要求，选择器和现有方案仍显示 Product，未执行写入。

最终结果：整体 pytest 回归 344 passed、17 skipped；启用 DESIGNER_TEST_VENDOR 的创建预检文件 24 passed（15 项单元测试、9 项现场 SDK 用例）。git diff --check 通过。测试期间修改桥接实现触发过一次来源漂移拒绝；稳定最终代码后重跑全部现场用例通过，证明旧实现结果不能进入缓存或确认。

现场边界还确认：用户明确指定 T_ExOwnerProbe 与 T_ExOwnerProbe_1 两张不同表时允许创建；带数字后缀的显式名称不被误判为厂商自动改名。聊天回归确认父对象选择未被应用会阻断，“其余要求不变”不会丢失原字段要求。
