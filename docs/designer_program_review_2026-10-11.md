# Designer 程序与文档复查（2026-10-11）

本报告记录修复前的发现。用户随后授权优化，修复结果与验证见 [程序优化记录](designer_program_optimizations_2026-10-11.md)。

本轮为审查和隔离验证，未修改业务实现，未执行数据库发布、数据库恢复或服务器工作 MDB 覆盖。

审查范围：Web 与 MCP 入口、聊天工作流与持久化、Excel 预览、官方元数据桥、固定工作 MDB、备份与恢复、Designer 交接、发布预检与验收、进度、WCF 生成与下载、启动脚本、测试及仓库文档。同时对照本地官方 Designer 手册 Release 2504+ Rev.1。

继续遵循已确定的产品要求：一个项目持续编辑同一个工作 MDB；发布后下一轮首次修改前备份，最多保留 10 份；测试库默认不强制数据库备份；多人合并与兼容由 Opcenter 处理。

## 1. 结论与优先顺序

已有能力覆盖了日常 CDO、字段、继承调整、事件、CLF 调用、查询、映射、设计交接和版本恢复。当前首先需要解决的是不同入口、最终状态和执行回执的一致性。本轮确认了 6 类实现问题，其中停止请求后的执行回执丢失、手动发布基线未经验收属于优先修复项。

新增能力建议依次推进：CLF 自身参数与 Query 参数类型管理；引用影响与重命名辅助；存储变更和物理索引验收；项目进度与长期使用的资源管理；服务运行验收。原生 XML Import 与 REST 可作为后续独立里程碑。

“可以读取一种定义”“可以修改部分属性”“支持其完整生命周期”“已验证业务运行”应分别记录，不能用同一个支持标记代替。

## 2. 已确认的实现问题

### R1 / P1：停止聊天请求后，后台保存继续，但最终结果丢失

位置：[工具执行](D:/Deepseek/camstar/CamstarDesignerMCP/agent/langgraph_runtime.py:344)、[线程中的设计操作](D:/Deepseek/camstar/CamstarDesignerMCP/tools/designer_design.py:187)、[取消时的进度回执](D:/Deepseek/camstar/CamstarDesignerMCP/designer/progress_store.py:110)。

设计、同步、发布等工具通过 `asyncio.to_thread` 执行。取消等待它的聊天请求不会停止已经运行的线程。当前取消分支却立即把操作记为 `interrupted`，后续线程成功返回的结果没有被保存。

隔离复现：工具线程开始后取消聊天执行，再允许线程完成模拟保存。文件确实保存了，但操作回执仍为 `interrupted`，`result=null`。因此最新文件与页面可见结果可能不一致，用户重试也无法明确判断上一轮到底完成了什么。

建议：写入类操作使用独立、持久的任务身份，与 SSE 连接分离；停止回答后仍记录后台任务的实际结束状态和清单；在安全阶段边界响应取消。无需强杀正在保存 MDB 或更新数据库的厂商进程。界面应如实提示后台操作是否仍在完成，并支持刷新后找回结果。

验收：保存期间停止回答后，操作最终呈现成功或真实失败，成功清单可被进度页发现；不会因断线重复执行同一写入任务。

### R2 / P1：手动确认发布直接建立“已验证”基线

位置：[手动基线](D:/Deepseek/camstar/CamstarDesignerMCP/designer/publication.py:86)、[进度确认](D:/Deepseek/camstar/CamstarDesignerMCP/designer/progress.py:391)。

在已有同目标发布基线的情况下，点击“手动更新确认”时，`record_manual_baseline` 把当前设计 MDB 的哈希与此刻 SQL 的指纹写入 `published_baseline.json`，状态为 `verified`；随后 `mark_published` 也把 MDB 记成已发布。这个流程没有先对照本轮最终设计检查 SQL 中的变更。

隔离复现：模拟数据库没有改变，手动确认仍把新的 MDB 哈希写成 `verified`，元数据验收函数没有被调用。错误文件、漏更新或只完成部分更新时，数据库指纹本身并不能证明 SQL 已经对应这个 MDB。后续发布检查和“上一版已发布 MDB”备份都会信任该关联。

建议：人员确认与程序验收分开。人员确认可以推进“用户已执行”状态；只有对整个设计周期的最终 MDB 完成 SQL 验收后，才替换已验证基线并建立已发布版本记录。验收失败或无法连接时保留原基线，显示具体未通过项。自动发布也应明确区分厂商更新完成、元数据验收通过与服务运行通过。

验收：SQL 未更新、更新了错误 MDB、遗漏字段或参数时，手动确认不能形成新的 `verified` 基线；完整更新并验收后才建立新基线。

### R3 / P2：聊天发布与进度页没有使用同一套连续设计计划

位置：[聊天工具的预检](D:/Deepseek/camstar/CamstarDesignerMCP/tools/designer_design.py:120)、[进度页合并周期](D:/Deepseek/camstar/CamstarDesignerMCP/designer/progress_actions.py:61)、[实际发布的基线检查](D:/Deepseek/camstar/CamstarDesignerMCP/designer/publication.py:423)。

例子：数据库对应 B0；第一次设计得到 B1；再次修改得到 B2。B2 单轮清单的来源是 B1。进度页会从本周期 B0 导出到最终 B2；聊天工具却直接对 B1→B2 的单轮清单预检，没有合并周期或核对已发布来源。

隔离复现：B1→B2 的直接预检返回 `ready_for_publish=true`，但它的来源哈希与已发布 B0 不同。实际发布已有检查会拒绝该来源。直接验收同样只覆盖调用者提供的清单范围，不能自动证明前一轮变更都落到了数据库。

建议：提取共用的“当前项目、当前设计周期、最终版本”计划入口，供 Web、聊天工具和 MCP 一起使用。返回同一份最终清单、目标指纹和哈希，避免模型自行寻找中间文件。最终发布继续保留现有来源校验。

验收：同一项目连续设计两轮，以及换聊天继续第三轮，通过三个入口得到相同的 B0→最终版本计划和验收范围。

### R4 / P2：WCF 检查使用操作历史，误判最终字段状态

位置：[设计摘要](D:/Deepseek/camstar/CamstarDesignerMCP/designer/operations.py:64)、[WCF 字段检查](D:/Deepseek/camstar/CamstarDesignerMCP/designer/progress_actions.py:183)。

已复现三个情况：

- 字段 `Old` 改名为 `New` 后，摘要的行名仍为 `Old`；程序集包含正确的 `New`，检查仍报缺少 `Old`。
- `remove_field_override` 恢复继承字段，但摘要给它标记 `deleted=true`；程序集保留合法继承字段时反而被拒绝。
- 同一周期先新增再删除字段，历史记录同时要求该字段存在和不存在；最终正确程序集也无法通过。

建议：保留操作历史用于展示，验收另行读取最终有效元数据，按稳定身份归并改名和增删，并考虑实际服务暴露配置。撤销覆盖意味着恢复父级定义，不能按最终字段删除处理。

验收：上述三种情况都根据最终契约判断；最终确实缺失或残留的字段仍能检出。

### R5 / P2：新增的操作计数没有正确累积到聊天执行状态

位置：[执行后的计数](D:/Deepseek/camstar/CamstarDesignerMCP/agent/langgraph_runtime.py:395)。

`count_tool_calls` 已经能识别设计包里的创建、修改、删除，但执行节点仍先按工具名的 `create_`、`update_`、`delete_` 前缀判断。`generate_designer_design_package` 等名称不匹配，因此实际完成的计数没有累积。

隔离复现：连续执行 4 次各包含 1 条修改的设计包；单次解析均得到 1 条修改，但最终累计修改数为 0。在当前修改阈值 3 下，第 4 次也没有触发累计确认。

建议：执行节点直接累加解析结果的三个分量，并明确成功、失败与已确认任务的计数语义。补执行节点回归，不能只测试计数辅助函数。

验收：分成多次调用的修改与单次批量调用得到一致的累计数量；混合创建、修改、删除包正确统计。

### R6 / P2：聊天用户名可以逃出会话存储目录

位置：[未约束的请求用户名](D:/Deepseek/camstar/CamstarDesignerMCP/web/routes.py:154)、[会话路径拼接](D:/Deepseek/camstar/CamstarDesignerMCP/agent/memory.py:27)。

`ChatRequest.username` 接受任意字符串，会话目录直接用用户名拼接。聊天入口也没有统一限制到当前配置身份。

隔离复现：用户名 `../outside` 被请求模型接受，创建会话时在 `SESSIONS_DIR` 的同级 `outside` 目录写入会话 JSON 和 `metadata.json`。复现仅发生在独立临时目录。

建议：所有 Web 入口统一身份检查；用户名采用允许的标识格式，拒绝分隔符、绝对路径与上级路径；解析后的存储路径必须仍在会话根目录内。当前单用户模式可先只允许配置用户。若作为共享服务使用，再补 Web 与 MCP 一致的身份认证；用户名归属校验本身不是登录认证。

验收：相对逃逸、反斜杠逃逸、绝对路径和非配置用户均不能写入会话根目录以外。

### CLF 参数应作为下一轮专用能力的重点

当前 `set_clf_parameter` 修改的是某一次函数调用的 `ValueExpression`，不是给 CLF 自身增加声明参数。读取 `clf_parameter`、修改其部分简单属性也不能替代新增及关系维护。

官方手册 6-7、6-22 明确区分 CLF 参数的名称、数据类型、方向与多重性；已绑定事件或方法的 CLF 增加参数后，还需处理绑定端的参数。建议先交付添加/修改 CLF 声明参数，再覆盖调用方和事件参数同步，确保能通过保存、回读、编译和执行用例。

### 引用分析要从“能删除吗”发展到“改了影响什么”

字段回退分析目前已覆盖字段映射、直接事件和继承覆盖，并明确 `complete=false`。这是合理边界。下一步应串联表达式、Query 文本、CLF 参数、事件、子类和数据库映射，提供具体受影响项。

文本匹配只能标为候选引用；稳定 ID 关系与厂商明确返回的引用应单独呈现。改名建议提供“旧名→新名及需要核对的表达式”预览，再按明确变更计划执行，不应自动强制删除引用。

### 存储验收需检查实际 SQL 对象

现有编译差异验收覆盖索引及列的元数据行，但物理检查主要针对字段与列。SQL 指纹检查列结构，没有包含 `sys.indexes` 与 `sys.index_columns` 的真实索引定义。

官方手册 8-21、8-22 区分索引定义、列顺序、升降序与使索引实际生效的步骤。因此应增加真实索引存在、唯一性、列顺序、排序方向等验收。这里没有断言当前 SDK 不会创建物理索引；本轮确认的是程序未提供足够的物理索引验收证据。

类型与长度变更还应预检目标数据：超过新长度的行数、转换失败数、唯一索引的重复键、非空约束的空值。查询只返回必要计数和摘要，测试库默认不强制备份的既定行为继续保留。

## 4. 长期使用与界面增强

### 4.1 临时产物保留策略

本轮只读统计：`data/designer/artifacts` 有 **141 个产物目录、185 个 MDB 快照，MDB 合计约 8.93 GiB**。该数字不包含工作项目备份目录。

[只读检索](D:/Deepseek/camstar/CamstarDesignerMCP/designer/vendor.py:65)每次都会复制整个 MDB；[产物目录](D:/Deepseek/camstar/CamstarDesignerMCP/designer/files.py:24)按 UUID 新建，当前没有对应的引用感知清理策略。保留 10 条 MDB 备份不会限制这些读取、设计、编译和验收快照。

建议按用途设置保留期；已完成只读检索优先清理。保护工作状态、当前设计周期、已发布基线、有效执行凭证和备份所引用的文件；先提供清理预览、预计释放容量与不可删除原因，再执行清理。检索缓存以 MDB 哈希、工作区、SDK 版本和请求参数为键，避免使用过期定义。

### 4.2 项目级进度与聊天分离

固定 MDB 已按项目管理，发布预检已尝试跨聊天合并当前周期，但页面任务与回执仍主要按聊天归属。

建议把项目的最新 MDB、当前发布周期、最新设计进度和备份作为主体；聊天负责解释与查看本轮结果。旧聊天继续设计后应能看到最新项目状态，历史版本提供明确只读视图，避免旧卡片给人“最新文件不可用”的印象。

这不涉及自行实现 MDB 合并。服务器与本地同时变化仍保留双方，由 Opcenter 合并后接收确定版本。

### 4.3 长对话、并发与结果恢复

最近对话 30 条和按更新时间排序已实现。它们限制的是会话列表，不能控制单个聊天给模型的上下文大小。[模型请求](D:/Deepseek/camstar/CamstarDesignerMCP/agent/langgraph_runtime.py:150)仍发送全部消息，包括大型元数据工具结果。

建议保存完整原始历史，同时压缩模型上下文：保留项目身份、最新哈希、已确认设计要求和未完成步骤；工具大结果用稳定引用按需取回。另补同一会话并发请求的序列化与检查点恢复测试，避免多标签页共享同一会话时相互覆盖消息。此并发项是代码审查建议，本轮没有跑真实多客户端竞争实验。

### 4.4 操作预览与版本对比

Excel 预览已有人员确认与参数指纹约束。下一步可让通用自然语言设计也输出统一的“当前值、目标值、受影响对象、对应 Excel 行或用户要求”预览。将改父、恢复覆盖、替换事件等操作名称转换成用户能理解的说明；撤销或恢复前展示内容差异。

### 4.5 能力诊断与安装版本兼容

[能力查询](D:/Deepseek/camstar/CamstarDesignerMCP/tools/designer_design.py:30)的多数布尔值依据 DLL 是否存在及配置是否填写，没有逐项探测方法、驱动、权限和真实可执行状态。

建议返回“已实现、依赖已就绪、当前可执行、真实验收覆盖”四层结果，附具体缺失原因。诊断分别核对 Python 与 ACE 位数、PowerShell 5.1、厂商程序集版本、可读路径、共享、SQL 权限及 WCF 作业条件。只做必要的只读探测，避免为了检查环境启动导入或数据库写入。
