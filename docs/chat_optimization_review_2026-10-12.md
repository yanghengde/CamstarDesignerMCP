# 聊天优化审查（2026-10-12）

本次为代码、会话记录和工具元数据的只读审查。未修改聊天实现，未调用 Designer 写入工具。下面区分已经确认的实现缺口与需要进一步复现的风险；优先级表示实施顺序。

## 已核实的重点

| 优先级 | 当前实现与证据 | 建议行为 | 验收方式 |
|---|---|---|---|
| P1 | `_agent_node` 将历史消息逐条放入模型请求，只移除 UI 元数据。审查时案例会话有 90 条消息，content 合计 1,040,916 字符，工具回执占 1,001,188 字符；此计数不含工具调用参数，也不是 token 计数。 | 完整记录保留在本地；模型读取近期对话、当前需求、最新有效证据及有界的工具摘要。大回执用证据 ID、路径、哈希和按需读取保留可追溯性。 | 长对话请求大小受预算控制；改名、工作区、建表要求、授权范围不因摘要丢失；原始回执可回读。 |
| P1 | `AgentState` 有消息、当前请求、待执行调用与审批状态，缺少独立的当前设计目标和验收要求。最新修正优先目前主要由提示词保证。 | 保存活动任务：目标、对象名、表名、字段、工作区、来源、最近明确修正及待解决问题；保留来源消息引用。工具计划必须与目标核对，例如要求物理表时不能把只建 CDO 视为完成。 | “改名后继续”只修改对应参数；插入查询后能返回原任务；要求建表时不会推荐不满足建表要求的方案作为默认完成路径。 |
| P1 | 待确认分支除了确认、取消、简短附和，其余文字均作为 `revision`；政策节点随即作废所有待执行调用。 | 区分参数修改、设计追问、状态查询、回复反馈、暂停、取消和新任务。追问只回答，保持待确认计划；明确修改才换预览。识别不确定时不执行或擅自作废计划。 | 待确认时问“为什么继承这个对象”“现在写入了吗”“回答短一点”，预览保持有效；“名称改成 6382”使旧预览失效。 |
| P1 | 通用设计工具实际 schema 为 `operations: array<object>`，object 允许任意属性，没有 required action；工具说明也没有明确每项必须有 action。预览生成器不会先调用 `validate_operations`，无 action 也能生成“设计变更”行。现有参数校验在设计工具后端调用阶段执行，能在 `_design` 的复制和 SDK 操作之前拒绝这些格式。 | 明确 action 字段与完整示例；尽可能用按 action 区分的结构化 schema。生成预览之前做不写文件的参数校验；错误反馈指出第几项、缺少什么、正确格式。避免要求人员确认必然失败的参数。 | 裸对象、op 键、操作名作键在预览前被拒；合法 action 格式通过；失败校验不调用 SDK 或设计保存流程。 |
| P2 | 经验库收集工具结果，审核后注入；尚无聊天内容反馈入口。检索主要依赖最近 8 条消息里的工具名，message 参数未用于匹配规则。 | 保存明确用户偏好与经验证的操作经验，区分当前任务要求和长期规则；支持替代、删除与适用范围。模型自评仅作为候选。检索结合任务类型、相关工具、项目和版本。 | 用户说“以后复盘简短”可在后续对话生效；临时“这次不要建表”不会改变以后全部任务；未经验证的模型自责不会成为事实。 |
| P2 | 模型输出直接流式展示，最终回复也直接使用模型 content；没有专门核对结论与本次工具回执的阶段。 | 把对象存在、已保存、已发布、未改变等关键结论绑定本次证据及其范围。复盘先读取日志和回执，再描述已确认原因与待核实部分。模型推测不转换为已核实事实。 | 失败时不能笼统宣称“没有任何写入”；工作 MDB 未变与失败副本、业务库状态分别说明；不能把未配置、未验证和不支持混为一谈。 |
| P2 | 确认文本为了模型工具消息配对，在整个批次工具结果后追加到消息列表。界面历史和模型消息未建立独立的时间线视图。 | 保存确认接收时间、预览 ID、参数指纹、执行起止及结果。模型继续保持合法消息配对；用户界面和复盘按照真实事件时间展示。 | 刷新后仍能证明“预览 → 用户确认 → 开始执行 → 结果”；复盘不会把模型消息顺序误判为执行顺序。 |
| P2 | 工具错误作为文字回给模型，路由继续到 agent；主要终止约束是累计操作计数和总循环次数，没有针对同类失败的恢复策略。已有进度回执可以复用相同 call_id 的结果。 | 分类处理参数错误、来源变更、环境缺失、业务冲突与暂时性读取故障。参数错误回到合同校验；来源变更重新读取；失败写入先核验实际状态。同一参数/来源版本的重复失败需要新证据才能再试。 | 不再通过更换 op、包装键反复试写；来源哈希变化后刷新真实定义；暂时性只读错误可以有限重试；不因新 call_id 盲目重复写入。 |
| P2 | `excel_preview.sources` 从整个会话倒序选最近一次附件，附件不绑定活动任务。后续无附件的新设计仍可能沿用历史附件和对应确认门槛。 | 附件绑定当前设计任务及方案版本；新任务明确结束旧附件适用范围，原设计续做继续保留附件。 | 同一对话上传表格后再设计无关对象，不被旧表格内容或旧附件失效阻塞；原批次继续修改仍校验原附件哈希。 |
| P2 | 系统提示词规定中文、专业简练，但没有针对执行、解释、失败、复盘分别规定回答内容。 | 执行结果默认简述本次结果、证据和下一步；失败说明错误所在与恢复动作；复盘说明已核实的原因和修正。用户已经确定的目标无需反复列 A/B/C 让其重选。 | 回复不会长篇自责；不重复已经给过的参数和决定；详细日志、路径、哈希放在可展开的证据中。 |

## 实施顺序

第一批：模型上下文预算与回执摘要、活动需求状态、待确认回复分类、预览前参数校验与明确的工具合同。这些直接影响能否按最新要求继续执行。

第二批：聊天反馈与长期偏好、结论与回执核对、真实确认时间线、按失败类型恢复、附件任务归属和不同场景的简洁回复规则。

第三批：建立覆盖真实模型行为的隔离对话评估。现有 fake-model 测试可验证状态机、审批和持久化，但不能证明实际模型理解修改、选对工具或基于证据回复。真实模型评估使用假工具或私有测试文件，避免影响用户工作 MDB。

## 需要进一步复现的风险

- 同一会话的两个页面可能同时发送请求。前端 busy 只约束当前页面；聊天入口没有看到会话级串行队列。需要并发复现确认检查点、历史消息和审批是否发生覆盖，再决定增加会话锁和请求幂等键。
- 全量上下文可能增加耗时、超限或削弱对最新要求的关注。这是由请求构造与体量推导出的风险；本次没有用线上模型测量影响，也没有把它断言为本案例每次误答的唯一原因。
- 目前没有逐项自动核实自然语言结论的阶段，但不能因此断言所有历史结论都错误。应以实际对话样本核验。

## 建议的对话评估样本

| 用户表达或场景 | 预期行为 |
|---|---|
| “6381 换成 6382，其他不变” | 保留原字段、工作区和建表要求；更换名称并检查受影响引用。 |
| 待确认时问“为什么这么设计？” | 回答理由及依据，保持原预览待确认。 |
| “确认，但长度改为 400” | 调整长度并生成新预览；不执行旧参数，也不把这句话当作尚未展示的新预览的确认。 |
| “先别创建，查一下 MfgOrder” | 执行只读查询；不继续写入；保留或明确暂停原设计上下文。 |
| “以后少点自责，先说事实和下一步” | 保存明确回复偏好；不把它当作设计参数修改。 |
| “刚才失败了，你复盘一下” | 依据调用日志、错误和工作文件状态报告；不把模型消息顺序视为执行时间线。 |
| 工具返回“未知设计操作” | 查明 action 合同并在内存中校验，不换格式反复调用写入工具。 |
| 长对话后再次修改对象名 | 最新修正保持生效，历史字段和授权范围不丢失，模型请求大小保持预算内。 |
| 失败调用后重复“继续” | 先判断已执行、未执行或结果不明，再决定从哪一步恢复。 |

观察指标：目标保留情况、参数修正准确率、重复追问次数、无依据的肯定结论数、同类参数错误重试次数、长期偏好复用情况、模型请求大小和首字耗时。审批、参数校验和工具执行顺序应作为确定性约束验证，而非仅依赖模型评分。

## 代码定位

- `agent/langgraph_runtime.py`：AgentState、全量历史请求、待确认路由、错误恢复与确认消息追加。
- `agent/excel_preview.py`：附件选择、预览生成和参数指纹。
- `tools/designer_design.py`：通用工具参数类型与操作说明。
- `designer/vendor.py`：validate_operations 及设计流程中的校验位置。
- `agent/experience.py`：失败候选、经验审核和工具名匹配。
- `static/index.html` / `web/routes.py`：消息时间线、结果展示和反馈入口。
- `tests/test_excel_attachments.py`：现有假模型状态机验证及可补充的对话场景。
