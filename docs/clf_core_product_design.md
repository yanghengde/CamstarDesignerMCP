### 术语与页面用语

| 名称 | 含义与用语规则 |
|---|---|
| 业务操作 | 用户要完成或排查的任务，如产品有效期检查；可以涉及多个 CLF |
| 业务记录 | 一次实际业务操作/请求的记录；仅有产品名称不等于唯一交易 |
| 规则 / CLF | CLF 是实现规则的一种技术定义；业务页显示已核实的业务名，工程页保留 CLF 真名 |
| 入口 / 绑定 | 在哪个对象、方法或字段事件附着并触发规则；与公开 WCF 服务方法不是同一概念 |
| 库定义 / 入口配置 | 规则的库中默认定义 / 某个具体入口实际附着的配置 |
| 检查 | 读取已有事实或执行明确的当前只读检查；不会隐含重新执行业务交易 |
| 验证 / 复现 | 用明确输入调用实际服务，再对照预期；可能写入，必须说明目标 |
| 方案预检 | 官方内存模型接受完整操作；不等于保存、部署或业务验证 |
| 轨迹 / 证据 | 服务器实际返回的跟踪 / 可以支持特定结论的来源信息；二者不等于定义顺序 |

## 1. 产品定位与成功标准

CLF 工作区是产品的业务规则核心：让使用者知道规则在哪里生效、为什么产生某次结果、怎样准备并验证改动，以及改动是否到达目标运行环境。

需要贯通的任务链为：

```text
业务问题 / 已知规则 / Excel 要求
                ↓
确定项目、业务入口与来源
                ↓
查看有效配置和已有运行证据
                ↓
准备测试 → 执行并核对预期
                ↓
准备变更 → 审核差异 → 官方预检
                ↓
后续：保存 → 构建 → 发布 → 部署核对 → 回归
```

核心质量要求：

1. 操作人员不需要先学会 CLF、CDO、WCF、调用 ID 等术语，就能查询一条已接入记录、看懂问题和下一步。
2. 工程师可从同一条记录进入真实定义、附着参数、运行轨迹和版本，不重新描述问题或反复选择项目。
3. 每个结论可追溯到来源；缺少证据时仍能继续排查，但不能把推断显示成已验证事实。
4. 日常查看与测试准备无需等待 AI；AI 用于解释与建议，服务调用和状态转换由确定性代码完成。
5. 变更范围、保存结果、发布结果和业务验证分别可见。一个绿色状态不能代表整个生命周期完成。

本模块质量通过任务完成率、误判率、响应时间和交付证据衡量，不能仅以页面美观、功能数量或模型回答长度验收。

## 2. 核心设计决定

| 编号 | 决定 | 对实现的要求 |
|---|---|---|
| D01 | 一个工作区，两种工作模式 | “业务检查”面向操作人员，“工程排查”面向工程师；模式切换保持同一条记录及来源 |
| D02 | 根据入口进入合适视图 | 无上下文进入时展示业务检查；已知 CLF 链接直达工程规则视图；旧测试链接直达工程验证视图 |
| D03 | 以业务操作映射连接业务与技术 | 映射必须由真实契约、绑定及验证证据支撑，不按名称相似自动确认 |
| D04 | 先看结果，再展开证据 | 操作视图显示结论、依据、下一步；完整参数、原文与报文在工程视图可达 |
| D05 | 库定义、入口配置、输入、运行值分层 | 缺失字段有明确可用状态，不能互相代替 |
| D06 | 定义顺序与实际轨迹分别记录 | 未知路径不着色为执行成功；重复函数以调用身份区分 |
| D07 | 查看历史不重新执行业务 | 复制为测试用例只准备输入；真实执行另有明确动作 |
| D08 | 不把聊天当作工作区的存储容器 | 浏览规则不创建聊天历史；首次真正提问才创建持久化对话 |
| D09 | 运行、业务返回、断言、规则证据、版本分别展示 | 总结文案由结构化状态推导，不能只显示“通过/失败” |
| D10 | 所有版本变化都可追溯 | 历史回执冻结原上下文；来源变化后显式重新核对，不自动篡改原记录 |
| D11 | 先建立证据和测试基础，再接通实施 | CLF 助手现有只读权限不因界面按钮、用户一句确认或模型输出而扩大 |
| D12 | 高级能力由实际支持程度决定 | 无断点会话时不提供可点击的暂停/单步；无部署证明时不显示部署一致 |

以下是本次核对仓库后的现状，不是待开发页面的完成说明。

| 能力 | 状态 | 现状与缺口 |

| 按对象、维护入口和父类筛选目录 | 已有 | 紧凑目录缓存；不是已确认的全部动态运行调用链 |
| 直接函数定义、函数参数和显式错误标签聚合 | 已有 | `analysis_context`；不自动展开所有子 CLF、callsuper 或动态调用 |
| 库定义与具体入口附着参数完整对照 | 新增 / 待验证 | 现有返回不足以提供完整的入口有效参数；需验证 `CLFEventMap` 及 SDK 访问方式 |
| 严格操作模型及官方内存预检 | 已有 | 十种现有 CLF 操作可预演；不保存、不发布，不证明表达式语义及业务正确 |
| 真实 WCF 测试、预期及字段断言、独立回读 | 已有 | 测试请求独立于模型循环；需简化表单与归属到当前排查上下文 |
| 持久化测试记录、用例、请求去重和刷新恢复 | 已有 | 专用 SQLite；当前运行状态不足以表达本方案全部分层状态 |
| 目标 CLF 名称触发证据 | 已有 | 仅明确的结构化名称属性；不证明具体调用行、参数值或全部路径 |
| 运行轨迹映射到具体函数行与参数值 | 增强 / 待验证 | 需要真实轨迹样本与稳定标识；不能按名字和行号猜测 |
| 业务操作中文目录、映射配置及失效管理 | 新增 | 当前对象筛选和入口推荐不是完整的业务操作映射系统 |
| 操作人员查询全部 MES 业务历史 | 新增 / 待接入 | 当前历史主要是本工具的测试回执；没有通用 MES 交易历史查询连接器 |
| 已保存测试记录的只读业务检查 | 新增 | 可先从本工具真实回执起步；不得用示例记录代替正式历史 |
| 工作区独立于聊天保存上下文 | 新增 | 当前多项 CLF API 依赖 CLF 会话；需提供无需空对话的访问与存储合同 |
| 参数声明的完整增删、类型/方向生命周期 | 后续新增 / 待验证 | 不能用函数调用参数的 `set_clf_parameter` 代替声明参数管理 |
| CLF 专用保存、构建、发布及验收闭环 | 后续增强 | 复用产品已有设计进度能力前，需核实 CLF 动作覆盖和独立回执合同 |
| 真正的断点、暂停、单步和运行时变量修改 | 待验证 | 当前代码设置 DebugRequest 并返回 Trace，没有调试会话 API |
| 企业多用户角色、共享及审批 | 后续新增 | 当前是本机工作台和归属校验，`CHAT_USERNAME` 不是企业认证/RBAC |

特别约束：本机厂商帮助明确指出，**修改库默认函数参数不会自动更新已附着入口的参数**。必须先读出差异和影响范围，不能把“同步默认值”实现成自动批量解绑、重绑。

## 4. 使用者与操作边界

这里的“操作人员、工程师、交付人员”先用于任务和界面分层，不表示系统已经有对应权限角色。模式切换只改变呈现；权限仍由服务端和当前部署合同决定。未来多用户部署前必须补上实际身份和权限。

| 任务 | 操作人员默认路径 | 工程师路径 | 后续交付路径 |
|---|---|---|---|
| 查一条记录为什么失败 | 选择业务操作、记录，看结论和下一步 | 查看入口、原始回执、规则与版本 | 不涉及 |
| 查看规则做什么 | 查看已核对业务摘要 | 查看真实定义、参数、声明、引用、继承 | 不涉及 |
| 规则没生效 | 准备排查信息 | 核对绑定、有效参数、部署版本和轨迹 | 核对实际部署证据 |
| 复现 | 复制输入供排查，不自动执行 | 选真实入口，配置预期并显式测试 | 提供目标环境及客户端 |
| 改规则 | 描述业务要求 | 明确修改范围，准备差异，预检与回归 | 后续审核保存/构建/发布 |
| 改连接、映射或跟踪配置 | 显示不可用原因及联系工程师动作 | 配置并验证，不在日常页重复填写 | 核对环境和部署关系 |

## 5. 信息架构、导航与持久化

### 5.1 全局结构

全局菜单保留“CLF 工作区”和独立“WCF 接口测试”。原“CLF 逻辑测试”作为兼容入口进入 CLF 工作区的工程验证页，避免长期维护两套不同上下文。

工作区内部：

```text
CLF 工作区
├─ 业务检查：业务操作 → 记录 → 结论 / 依据 / 下一步
├─ 工程排查
│  ├─ 查看逻辑：定义、入口、参数来源、在哪里使用
│  ├─ 验证与排查：输入、预期、真实回执、轨迹、运行对比
│  └─ 修改方案：业务要求、差异、影响范围、预检、实施交接
└─ 按需入口：运行历史、测试用例、业务映射配置、来源详情、助手
```

“业务检查 / 工程排查”是模式；“查看逻辑 / 验证与排查 / 修改方案”是工程模式内页签。不要再增加同级的“调试中心 / 测试中心 / 规则助手”重复入口。配置入口使用单独抽屉或页，不混进操作人员主流程。

### 5.2 统一上下文

工作区维护：当前项目、Designer 工作区、工作 MDB 来源、业务对象、业务操作映射、所选 CLF、具体绑定入口、环境、客户端产物、用例和运行记录。字段允许尚未确定，页面不能用任意默认值补齐。

上下文优先级：用户显式选择或可信深链 → 当前已保存工作区 → 唯一且兼容的配置。存在多个有效候选时要求选择一次；不能默默跨项目、跨环境选择。

模式和页签切换保留选择与未提交草稿。切换项目、入口或环境时按第 10 节失效规则处理，不继续展示另一上下文的绿色结论。

### 5.3 聊天与工作记录

- 打开工作区、查看规则、切换模式不保存聊天，也不产生“新对话 N”。首次实际发送问答时才沿用现有空对话不落历史的规则创建对话。
- 工作区选择、测试用例、运行记录、变更方案分别保存，不伪装成聊天消息。未发生有意义操作的空工作区只保留本地呈现状态。
- 首期工作区按本机当前用户归属；服务端加载项目、运行、草稿时继续校验归属，不信任前端传来的用户名或路径能授权访问。
- “新建排查”清空当前记录、临时结果和测试草稿；保留用户明确固定的项目/环境。不会删除已有回执，也不会新建空聊天。
- 旧 CLF 聊天、Excel 来源和深链可导入工作区上下文；保留原 ID 和来源，避免复制出不一致的记录。

## 6. 业务操作映射：易用性的前提

### 6.1 映射内容

业务操作是经工程师配置的任务入口，例如“产品有效期检查”，不等于单个 CLF。一个操作可以关联多个目标 CLF；一个 CLF 可以用于多个业务入口。

一条映射至少包含：稳定 ID 和修订号、业务名称/说明、适用项目和环境、业务对象类型、真实服务及方法、真实入口/绑定标识、目标 CLF 集合、输入表单映射、记录识别字段、只读检查方式、测试副作用分类、来源证据和核对状态。

中文名是显示信息；服务签名、CLF 身份、绑定 ID 和来源才是调用依据。不得把“产品”统一映射到 ProductMaint，或将自定义方法名当作可直接调用的 WCF 方法。

### 6.2 配置流程

1. 选择项目、工作区、已验证客户端和目标环境。
2. 从真实契约选择服务/方法，从官方引用选择候选绑定；无法自动匹配时明确人工补充来源。
3. 选择目标规则，核对直接/继承/客户覆盖及参数来源。
4. 配置业务输入、记录身份、期望提示和读取范围；使用真实契约类型校验。
5. 先保存为“草稿”，完成验证后标为“可用于查看”；可否真实测试单独判断，不因查看可用就允许执行。
6. 在业务目录中展示。缺少运行证据时，入口可显示“绑定已核对，运行未确认”；不能写成完整业务链已验证。

来源、服务签名、环境修订、绑定身份或有效参数变化时标为“待重新核对”。历史记录继续使用原映射快照，新请求不能静默套用旧映射。

### 6.3 历史数据接入顺序

首期记录来源限定为**当前用户有权访问的本工具真实测试回执**；业务名称仍须有映射。映射尚未建立时，页面给出工程配置入口，不显示假业务目录。

后续接入 MES 历史时，为每种来源单独定义：查询接口、身份/权限、记录主键、交易时间、环境、分页、可采集的输入/回执/轨迹及缺失项。业务对象名称不能唯一表示一次交易，必须保留交易或请求身份。

没有历史回执时可显示“当前资料检查”，但这是当前状态分析，不能当作历史交易重建。若当前没有可验证的只读检查合同，该动作不开放；不使用本地伪表达式执行替代服务器逻辑。

## 7. 业务检查页面与完整操作流程

### 7.1 页面 B01：开始检查

首屏只有业务操作、记录选择/查询、当前环境简名和一个主动作。项目与环境可见；路径、哈希、服务签名放在来源详情。存在多个环境时必须明确选择，不能因简化而隐藏实际目标。

业务目录按已配置任务展示，不默认列出几千个 CLF。搜索支持业务名和已核实说明。记录显示身份、业务时间、结果摘要和来源；“暂无记录”与“查询失败”是不同状态。

主动作按可用数据命名：“查看结果”读取已有回执；“检查当前资料”用于明确支持的当前只读检查。这里没有通用“执行规则”按钮。

### 7.2 页面 B02：检查结果

首屏按固定顺序显示：

1. **结论**：实际业务返回或当前检查发现，例如“业务已拒绝：产品不在有效期”；有推断成分时用“可能”，并标出依据缺口。
2. **依据**：业务记录、实际环境、发生时间、回执来源，以及解释结论必要的字段；当前读取值和交易时输入分栏显示。
3. **下一步**：最多两项与当前证据匹配的可执行建议；主动作优先解决当前未决问题。

目标规则没有触发证据时，结果标题明确“尚不能确认目标规则是否执行”，即使业务返回成功也不能显示为完整规则检查通过。

状态与文案示例：

| 实际情况 | 面向操作人员的表达 | 下一步 |
|---|---|---|
| 收到明确业务拒绝与错误提示 | 业务已拒绝，显示原提示及必要业务说明 | 核对相关配置；需技术分析时准备排查信息 |
| 收到业务成功，目标规则有名称证据 | 业务返回成功；显示已取得目标规则名称证据 | 有配置预期时看是否符合，否则不评价全部业务正确 |
| 收到业务成功，没有目标规则证据 | 业务返回成功，规则是否执行尚未确认 | 核对入口或补充跟踪 |
| 只有当前数据提示日期异常 | 当前资料存在可能问题，历史原因未确认 | 查看交易时数据或补充回执 |
| 调用曾中断或超时 | 未取得完整结果，实际业务状态待核对 | 查看原请求、核对记录；不直接重试 |

### 7.3 页面 B03：交接工程排查

“准备排查信息”生成可查看的排查包：业务记录身份、来源、已取得输入、回执、轨迹、环境/版本快照、缺失项、用户补充说明。不自动发送邮件或消息。

“进入工程排查”保留同一记录；默认定位异常或首个缺失证据。工程师可以返回原业务结果，不丢失输入和结论。不能把当前记录的新查询结果覆盖旧交易证据。

## 8. 工程排查：规则、参数与来源

### 8.1 页面 E01：查看逻辑

主区域由“规则与入口说明、函数列表、选中函数详情”构成。全局目录可收起，助手按需展开；不能把参数挤回狭窄侧栏。

- 规则目录提供最近查看、当前对象相关、客户规则及全部技术搜索；分页、搜索和按需读取，不预先展开全库。
- 标题保留真实 CLF 名称和中文说明。厂商说明、人工核对说明、AI 草稿分开标记。
- 顶部始终显示当前是“库定义”还是“某入口配置”；存在多个入口时选择具体绑定实例。
- 函数列表保留顺序、启用状态、真实函数和调用 ID。相同函数多次调用不得合并。
- 默认显示简短业务描述，完整表达式可直接展开；复杂结构保留原始顺序，不能为了简洁丢掉分支、跳转、异常或副作用。
- 子 CLF、callsuper 按需展开，保存父路径；循环引用停止展开并显示引用，不无限递归。
- 若函数/标签/引用读取失败，显示局部失败及影响范围，已取得的定义仍可查看。

可可靠识别的简单条件可用“条件 → 结果”表辅助理解；这不是 DMN 迁移或新的规则执行器。原始表达式、数据类型和调用身份始终可达。

### 8.2 页面 E02：参数四层对照

选择函数后并排显示下表；参数名、方向、类型、多重性及动态属性按官方定义读取，解释不替代原文。

| 层次 | 必须显示 | 缺失处理 |
|---|---|---|
| 库定义 | 函数参数的默认表达式、CLF 声明与来源 | 未读取或读取失败 |
| 入口配置 | 所选绑定实际附着值、直接/继承/覆盖来源及身份 | 未选入口、接口暂不支持或读取失败，不复制默认值冒充 |
| 本次输入 | 请求中实际提交值及其字段来源 | 未提交、null、空串、0、false、空列表分别表示 |
| 运行值 | 服务器在本次调用上下文中提供的解析值 | 未采集、不适用或截断；不在浏览器重新求值 |

差异提示分为“库与附着配置不同”“当前输入不同”“版本不一致/待核对”，不合并为一个模糊的“参数异常”。差异本身不等于错误，是否符合业务要求仍需判断。

### 8.3 页面 E03：在哪里使用与调用关系

按官方引用列出对象、字段、方法/事件、绑定身份与来源。支持从引用切换具体入口，从子调用回到父上下文。显示引用范围、总数、截断和动态调用覆盖情况。

“无已声明引用”与“实际不会执行”不同。只有当前工作 MDB 的引用不能证明目标服务器使用相同版本。无法完整确认的动态调用保持“待核对”。

### 8.4 表达式、声明与复杂逻辑

工程详情同时提供函数参数和 CLF 声明两个区域，避免把“传给某次函数的参数”与“CLF 自身参数声明”混在一起。声明按官方类型、方向、多重性和生命周期展示，未支持完整编辑时保持只读。

表达式编辑分业务表单和原文两种入口。只有模板能无损表达现有逻辑时才允许表单编辑；否则以原表达式为主，业务说明为辅助。不能来回切换后重写操作符、空值条件、时区或作用域。输入时只做已支持的类型/语法检查，官方预检和真实语义验证分别执行。

首期不提供任意拖拽重排来替代完整变更方案。后续支持重排时必须展示原顺序与拟定顺序、涉及调用身份、块结构及子调用影响，预检后再交接保存。不能仅因列表拖拽完成就视为逻辑正确。

## 9. 验证、轨迹与历史复现

### 9.1 页面 E04：准备验证

从规则或记录进入时继承项目、CLF、映射、环境与原来源快照。入口有歧义时列出真实候选及来源；只看到抽象方法时显示“实际服务入口未确定”。

普通输入使用真实契约生成的业务表单，高级模式保留 JSON。两种模式切换不改变数据含义，也不能丢弃表单不能表示的嵌套字段。字段支持“不提交 / 提交值 / 显式 null”等真实状态；null 是否清空由客户端和业务合同决定。

预期包括：业务成功或业务拒绝、可选提示、已有 exists/equals/contains 断言、是否要求目标 CLF 证据。正常/异常/边界仅为用例分组；新建议均为未执行。

提交前展示操作、环境、目标记录、真实服务/方法、可能写入影响和未核对版本。已知只读方法以现有服务端白名单为准；其他方法按可能写入处理。保存用例不保存本次写入授权。

### 9.2 页面 E05：运行与结果

主动作“开始验证”。服务器先持久化请求和幂等 ID，再执行。双击、网络重试和刷新只恢复同一请求，不重复提交。执行等待时显示真实状态；目前后台锁等待不应伪造为已调用业务服务器。

结果固定分为五层，独立显示：

1. 请求执行：准备、等待、调用中、已返回、异常、中断或结果未知。
2. 业务返回：成功、业务拒绝或未知，保留原始提示。
3. 用例断言：符合、不符合、部分未评估或未配置；预期拒绝且实际拒绝可以符合预期。
4. 目标规则证据：已取得明确名称证据、未取得或无法判断；具体函数行另行判断。
5. 来源与版本：工作 MDB、构建输入、客户端、环境修订和实际部署关系，分别核对。

已有 `status=passed`、`runtime_verified` 不直接作为“已部署版本验证通过”展示。完整验收还需要部署来源链、指定用例范围和回执完整性证据。

若写入成功后独立 Load 回读失败，结果必须保留“原写入已收到成功返回，回读失败”。不能提示“未保存，请重试”。截断内容不能用于未覆盖字段的通过结论。

### 9.3 页面 E06：实际轨迹

与规则定义保持两个数据视图。先突出首个可定位异常，允许按调用树展开。实际有时间时显示耗时；无时间、值或标识时显示未采集。

匹配规则：先核对来源版本，再按运行调用身份、调用路径和出现次序建立可证明的关联。同名函数、循环和递归不得仅按名称绑定到第一行。只有目标 CLF 名称时，只能确认 CLF 级证据，不能给每个函数行填绿色状态。

版本无法证明一致时，可并排查看，但不标为精确逐行对应。未执行、未采集、未展开和无法匹配是不同状态。服务器没有轨迹时保留业务结果；不能补造路径。

### 9.4 页面 E07：历史、用例与对比

历史按运行时间显示，记录原项目、映射修订、输入、预期、环境、来源和回执。历史是不可变事实；用户补充说明、重新核对结果或新的执行形成关联记录。

“复制为测试用例”只产生草稿，保留来源运行 ID 和原版本。可以用原版本复现或转到当前版本，但必须明确选择并重新核对差异。真实执行产生新运行 ID，不覆盖旧记录。

两次运行对比先显示输入、版本、映射、环境和断言范围差异，再比较结果。不能将不同记录、不同环境的数据直接解释为代码修改效果。回归首期串行执行，保持当前运行可靠性；未完成环境与客户端隔离验证前不启用并发业务写入。

## 10. 上下文切换与异常状态

| 触发 | 必须保留 | 必须失效/重新核对 | 用户可做什么 |
|---|---|---|---|
| 切换模式/页签 | 当前记录、入口、草稿和已完成回执 | 无 | 继续同一任务 |
| 切换 CLF | 项目、可兼容环境、原草稿索引 | 不兼容绑定、当前选择的参数和新运行摘要 | 查看库定义或选择新入口 |
| 切换绑定 | 同一库定义、原历史记录 | 入口参数、映射证据、依赖此入口的方案检查 | 重新读取有效参数 |
| 工作 MDB 更新 | 旧快照、旧方案与回执 | 当前读取、预检、目录缓存和待提交方案 | 查看差异并重新预检 |
| 环境/客户端变化 | 原运行快照、业务输入草稿 | 真实调用准备及部署核对 | 重新核对，不静默移植授权 |
| 请求执行中离开/刷新 | 服务器任务与请求 ID | 页面旧轮询 | 恢复同一任务，不再次 POST |
| 请求执行中切换任务 | 原任务及关联上下文 | 不将旧任务结果挂到新任务 | 用任务入口查看原运行 |
| 查询未匹配 | 用户输入 | 无 | 修改条件；显示零结果 |
| 读取接口失败 | 已有旧数据及其时间 | 不能把旧数据当本次成功结果 | 重读明确只读请求，或查看旧快照 |
| 调用超时/连接断开 | 请求 ID、已收到响应及时间 | 不得推定未写入 | 查原记录和实际业务状态 |
| 部分引用/回执截断 | 已取得部分、截断范围 | 未覆盖部分不能判通过 | 缩小查询或补充证据 |

输入未提交的草稿自动保存到当前草稿身份；切换时给出“已保留草稿”，避免每次切换弹确认。后续明确丢弃操作提供可恢复期限或可撤销动作。删除项目/用例的规则单独定义，不顺带删除运行证据。

## 11. 证据、版本与可解释性

所有视图都应能回答“来自哪里、覆盖什么、还缺什么”。业务结论、元数据事实、逻辑推断、人工说明与 AI 建议分别标记。

证据至少包括：来源类型/记录 ID、项目和环境、采集时间、源版本、完整性/截断、读取范围、可用状态和原文定位。错误信息不是正常空值；未采集不是 null。

需要区分的版本：

| 版本对象 | 能证明什么 | 不能自行推定什么 |
|---|---|---|
| 当前工作 MDB 哈希 | 本次读取/预检使用的设计源 | 服务器已部署该设计 |
| 构建输入及编译输出 | 某次构建使用的来源和输出 | 数据库/WCF 均已更新 |
| 客户端产物哈希及生成回执 | 调用契约与某次产物 | 与当前 MDB 或服务器完全一致 |
| 环境配置修订 | 调用目标和配置快照 | 实际部署版本 |
| 发布/部署回执及目标回读 | 对应目标中的已核对变更 | 所有业务场景均正确 |

已知冲突显示“不一致”；没有证据显示“待核对”；两者不能混用。后续建立设计、构建、发布、客户端、运行记录的来源链后，才启用“该部署版本回归通过”的汇总。

## 12. 修改方案与后续实施闭环

### 12.1 页面 E08：需求、方案与差异

方案页面提供“业务要求、变更差异、影响入口、测试计划、检查回执”五个区域。主动作随实际能力和状态变为“检查方案”“重新检查”或后续“交接实施”，不使用一个含义不明的“确认”按钮。

新建、复制、调整和重新绑定是四种不同任务：

| 任务 | 必须先明确 | 结果与下一步 |
|---|---|---|
| 从业务要求新建规则 | 需求来源、目标对象/入口、CLF 类型、工作区、参数及预期 | 可先形成未绑定规则草稿；没有真实入口不能称已生效 |
| 从已有规则建立客户副本 | 原规则来源、客户名称/类型、调用与参数、原引用范围 | 复制完成不自动替换原使用者；单独准备绑定差异 |
| 调整现有规则/参数 | 修改目标层次、调用身份、原值、拟定值、范围 | 显示业务差异和真实操作；保留未修改部分 |
| 替换或新增入口绑定 | 真实对象/字段/事件、原绑定、继承关系、附着自定义值 | 显示将新增/替换/保留的入口；补充前后测试 |

Excel 需求按原表/单元格关联到方案项；自然语言要求保留原文。多条要求分别标记已覆盖、待澄清、不在本次范围，不能仅生成一个大段说明就宣称全部已实现。

修改差异同时提供业务语言与技术位置：调用/参数/绑定身份、原值、拟定值、来源和受影响入口。未确定事项要具体，例如“实际服务入口未匹配”，不能泛化为“请人工检查”。方案可保存草稿并恢复，源变化后旧预检失效，要求和差异仍保留供重新核对。

### 12.2 首期：设计与预检

修改方案以“业务要求、目标范围、修改前后、影响入口、待决事项、预期测试”组织。目标必须明确为库默认值、具体入口附着参数、客户副本/覆盖或声明参数，不能只写“改规则”。

已有十种操作仅按实际支持范围使用。尚未支持的附着参数修改或声明生命周期显示不可实施原因，不伪造为普通调用参数变更。

系统/共享规则优先展示客户扩展方案；影响分析同时说明直接引用、继承、动态引用未覆盖部分。批量重绑必须保留入口自定义值并有差异依据，不作为修复参数不生效的快捷动作。

方案检查使用完整操作、真实调用 ID、原值和源哈希，返回官方内存预演前后结果。检查通过只表示官方模型接受；表达式语义、业务场景、保存、部署均独立。AI 建议的测试保持未执行。

### 12.3 后续：可实施变更

接通以下能力后才能启用“保存变更”：

1. 支持范围明确的写入执行器及服务端权限；不能扩大 CLF 只读工具列表来绕过交接。
2. 原值、身份、来源哈希和影响范围校验；共享项目有写入锁或乐观并发控制。
3. 在隔离副本应用完整变更，官方保存后回读并生成差异与回执；失败不覆盖唯一可用的原项目。
4. 保存前快照与可验证的恢复方式。文件恢复、数据库恢复、服务器文件恢复分别处理，不宣称跨系统原子回滚。
5. 声明参数变更时检查类型/方向/作用域、多重性、所有附着实例和调用者兼容性。

后续生命周期按独立回执推进：

```text
方案草稿 → 预检通过 → 审核可实施 → 已保存并回读
           ↓ 源变化需重检                ↓
        冲突/待补齐           已构建 → 数据库发布 → 服务器/客户端交付
                                           ↓
                                  部署关系核对 → 指定用例回归
```

每一步可失败或待核对，已完成的上游事实保留。例如数据库已更新但 WCF 交付失败，必须显示部分完成和恢复建议；不能把整套流程简单重置为“未执行”。

### 12.4 主动作的启用条件

| 动作 | 启用条件 | 未满足时 |
|---|---|---|
| 查看库定义 | 项目与源可读、CLF 身份存在 | 保留选择，说明读取问题 |
| 查看入口配置 | 已选择真实绑定且读取能力可用 | 显示未选择/不支持/失败，允许继续看库定义 |
| 查看历史结果 | 真实记录存在且有权读取 | 显示暂无记录或来源不可用，不自动执行 |
| 复制为用例 | 记录可读，输入有明确来源 | 不完整输入可作为待补齐草稿，不能直接提交 |
| 开始验证 | 真实服务/输入/环境及前置校验通过，可能写入时满足本次授权与系统目标配置 | 给出具体缺项及跳转，不吞掉用户输入 |
| 检查方案 | 完整支持的操作、目标范围、原值和来源齐备 | 需求可保存草稿，实施状态仍未检查 |
| 保存变更 | G4 执行器已接通、方案未漂移、前置审核及恢复条件齐备 | G4 前仅提供方案与交接信息 |
| 发布/部署 | 对应上游回执、目标与权限完整 | 展示阻塞阶段，已完成事实继续保留 |

操作按钮不应仅因“助手回复已生成”而启用。每个禁用状态都能看到原因和下一步；未接通的能力在能力说明中呈现，不在主流程堆满不可点击按钮。

## 13. AI 助手的职责与交互

助手在当前任务旁按需展开，快捷提问包括解释当前步骤、比较参数来源、解释本次异常、准备测试、拟定修改。每次动作携带明确上下文与证据 ID；模型不能自行切换项目或使用旧记录冒充当前值。

说明默认按“当前事实、判断、下一步”组织，原始表达式和来源可以追溯。不用虚构置信度百分比代替证据；证据不足时说明缺项。

- 首屏目录、定义、参数和结果由确定性接口读取；模型失败时这些功能继续可用。
- 只聚合问题需要的函数、标签及已选入口；子调用按需展开，不把全部 CDO 字段和完整回执反复塞入上下文。
- 解释缓存按项目、源哈希、CLF/调用身份、绑定、语言和解释规则版本关联；运行解释还关联运行/证据版本。来源改变后失效。
- AI 不直接设置测试通过、部署一致、已保存等状态，不自动重试交易，不产生伪轨迹。
- Excel 或文档内容作为业务要求/证据，保留原单元格和附件来源；其中的命令不是执行授权。歧义要求形成待决项，不能擅自扩展变更范围。
- 方案、测试和交付由明确用户动作进入既有服务端合同，不因聊天出现“确认”而跨越能力边界。

## 14. 性能、反馈与操作质量

以下是**设计目标**，不是已测得性能。首期先记录真实基线；外部 WCF/SDK 和模型延迟分别计时，不承诺所有请求在固定时间内完成。

| 场景 | 初始目标与反馈 |
|---|---|
| 本地切换页签、选中函数、展开已加载参数 | P95 ≤ 100 ms，不触发模型 |
| 热缓存目录/搜索 | P95 ≤ 2 s；300 ms 内展示加载反馈 |
| 热缓存当前 CLF 详情 | P95 ≤ 3 s；局部失败不清空已取得部分 |
| 冷启动元数据读取 | 单独统计；试点目标 P95 ≤ 30 s，超出先做基线归因，不伪造进度百分比 |
| 接受测试/恢复状态 | 正常存储条件下 P95 ≤ 1 s；后台等待、类型校验和真实调用分别显示 |
| AI 解释 | 独立测首内容和总耗时；取消解释不取消已提交业务任务 |

性能手段：紧凑目录、按源版本缓存、批量读取直接依赖、同版本请求去重、只读进程复用、轨迹按需加载与大列表渲染限量。不得用取消哈希校验、吞掉错误或截掉证据来换取表面速度。

操作要求：

- 以 1440/1024 桌面使用为主，736 和 320 像素仍可完成核心查看；窄屏分段显示，不压缩成不可读多栏。
- 状态同时有文字和形状/图标，不仅依赖颜色；日期显示时区，哈希可复制完整值。
- 键盘可完成选择、查看、准备测试；焦点位置合理，错误指向字段并保留输入。
- 每个区域一个主要动作；复杂配置渐进展开，但当前环境、写入影响和证据缺口不能隐藏。
- 网络中断、模型失败、SDK 失败有不同反馈；仅对明确只读请求提供安全重读，不自动重放业务调用。
- 耗时统计包括等待、SDK、网络、模型和渲染，避免把排队时间误当系统接口慢。

## 15. 功能分期与放行条件

阶段依赖是质量门槛，不是排期承诺。详细任务与验收见附属文档。

| 阶段 | 交付内容 | 必须满足的放行条件 |
|---|---|---|
| G0 证据基础与设计验证 | 业务映射样例、绑定参数读取验证、真实轨迹样本、数据来源盘点、场景试用 | 能说明每项数据是否可取得；无证据能力不得用正式按钮承诺 |
| G1 核心查看与排查 | 独立工作区、两种模式、真实目录与函数、四层参数、映射和本工具回执入口 | 不创建空聊天；上下文正确；读取缺项明确；历史查看无业务写入 |
| G2 验证与复现 | 共享测试上下文、真实表单、分层结果、历史复制、持久化恢复、用例分组 | 请求不重复；未知结果不自动重放；原回执与版本完整保留 |
| G3 工程效率增强 | 经验证的轨迹关联、运行差异、入口参数差异、影响分析和业务摘要 | 不猜测执行路径；版本/重复调用/截断情况下仍正确降级 |
| G4 变更实施与交付 | CLF 保存回读、声明生命周期、客户扩展、构建发布交接、部署来源链和回归 | 完整前置校验、恢复预案、部分失败可处理；不能越权写入 |
| G5 扩展与规模化 | MES 历史连接器、共享目录/用例、角色审批、受控批量验证、可验证调试会话 | 各子项单独完成来源/权限/厂商能力验证，不作为一次性大版本捆绑承诺 |

G1 可分步开发，但业务映射或真实记录未准备好时，正式页面必须展示未配置状态，不能用原型数据填充。若绑定参数完整读取暂不可行，可以先提供库定义查看并明确缺口；不能将该降级版本验收为完整入口排查能力。

建议试点至少包括 5 名未参与设计的操作人员和 3 名熟悉现场规则的工程师。以下为初始目标，需记录实际数据；人数及时间不是已经完成的用户研究结论。

不能用单次成功演示替代未知结果、无轨迹、来源变化、继承参数、重复函数、回读失败和网络中断场景。任何造成重复交易、错误通过或跨上下文结果混用的问题都阻止对应阶段放行。

## 17. 后续必须增加的内容与当前不承诺项

以下均已纳入附属任务表，不让核心设计停留在首屏布局：

- 业务操作映射的建立、修订、核对、停用和来源失效。
